# Wisdom Repo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> This is the **master plan**. It defines frozen contracts that all three phase plans must respect, and it lays out the dispatch + merge sequence. Three companion files contain the task-by-task work:
>
> - [Phase 1 — Capture core](./2026-05-13-wisdom-p1.md)
> - [Phase 2 — Site](./2026-05-13-wisdom-p2.md)
> - [Phase 3 — Imports + admin](./2026-05-13-wisdom-p3.md)

**Goal:** Build a personal wisdom repository: capture snippets via terminal CLI or agent slash-command, auto-categorize into closed buckets, commit per snippet, and serve a searchable neo-brutalist GitHub Pages site at the repo's Pages URL.

**Architecture:** Markdown-per-snippet (Jekyll collection) + a zsh CLI launcher + a single `SKILL.md` shared across Claude/Codex/Devin via per-engine symlinks. Site is Jekyll with Pagefind for client-side search. URL ingestion uses a 3-layer pipeline (yt-dlp → Playwright MCP → vision-LLM extraction) plus Whisper for spoken wisdom.

**Tech Stack:** zsh, Jekyll (github-pages gem), Pagefind, yt-dlp, Playwright MCP, whisper.cpp, ffmpeg, ULID, sha256, ripgrep, Anthropic Claude CLI (and Codex / Devin CLIs as alternates).

**Ownership conflict surfaces — already engineered out:**

- `bin/wisdom` — P1 writes the dispatcher with **all** subcommands enumerated, each routing to its `_wisdom_<sub>` function defined in its own `lib/cmd_*.zsh` file. P1 ships stub `lib/cmd_*.zsh` files for P3's subcommands that print `not implemented yet` and exit 0. P3 replaces those files with real implementations. No merge conflict on `bin/wisdom`.
- `docs/USAGE.md` — P1 creates with sections for capture + a placeholder `## Site (Phase 2)` and `## Imports (Phase 3)` headings. P2 and P3 append their sections under those headings (append-only, no overlapping edits).
- `tests/cli/` — P1 names its test files with `test_capture_*.zsh`, P3 uses `test_admin_*.zsh` / `test_import_*.zsh`. No filename collision.

### C2. Wisdom file schema (frontmatter)

```yaml
---
id: 01jabcdefghjkmnpqrstvwxyz0           # ULID, 26 chars, lowercase Crockford base32
created_at: 2026-05-13T14:32:00Z          # ISO 8601 UTC
updated_at: 2026-05-13T14:32:00Z          # optional, present only if edited
body_hash: a3f5c2...                       # sha256 hex of normalized body
category: engineering                      # key from _categories.yml
tags: [debugging, systems]                 # array of lowercase hyphenated strings; may be []
source_url: https://...                    # string or null
source_author: Rich Hickey                 # string or null
note: ""                                   # string, may be empty
import_origin: null                        # null | "file:<path>" | "url:<url>" | "manual"
---

<body markdown here>
```

**Body normalization** (used for `body_hash`):
1. Trim leading + trailing whitespace
2. Collapse any run of whitespace (incl. newlines) to a single space
3. Lowercase
4. sha256 hex

**ULID format:** lowercase 26-char Crockford base32. Generation via portable zsh function in `lib/_shared.zsh` (no external binary required). Implementation in P1 Task A3.

**Filename:** `wisdoms/<YYYY>/<MM>/<ulid>.md`, where YYYY/MM derive from `created_at`.

### C4. CLI surface

```
wisdom                                  # launch agent session, skill auto-engages
wisdom "snippet text"                   # one-shot, agent pre-fed
wisdom -                                # stdin one-shot (echo ... | wisdom)
wisdom -e                               # opens $EDITOR with template, then one-shot
wisdom --engine claude|codex|devin      # engine override (also WISDOM_ENGINE env)
wisdom ls [--bucket KEY] [--limit N]    # list, default limit 20, recent first
wisdom show <id-prefix>                 # show one wisdom
wisdom find <query>                     # ripgrep across wisdoms/
wisdom edit <id-prefix> [--no-recat]    # $EDITOR + optional re-categorize via skill
wisdom rm <id-prefix>                   # git rm + commit (with confirm)
wisdom import <file> [--format FMT] [--dry-run]
                                        # FMT: md | json | csv | txt | notion-export (auto if omitted)
wisdom import-url <url> [<url>...] [--engine ENGINE]
wisdom help | --help | -h
wisdom version | --version
```

## Dispatch + merge sequence (main session)

Steps for the dispatcher (this session):

1. **Plan commit.** Commit the four plan files (this one + P1 + P2 + P3) plus the existing `.agents/`, `skills-lock.json` so worktrees fork from a real ref.

2. **Bootstrap commit.** Commit the shared contract files that ALL three phases depend on, so each worktree forks with them present:

   | File | Contents source |
   |------|-----------------|
   | `.gitignore` | C11 (verbatim) |
   | `LICENSE` | dual MIT + CC BY 4.0 (P1 Task A1 Step 2 has the exact text) |
   | `wisdoms/_categories.yml` | C3 (verbatim) |
   | `AGENTS.md` | P1 Task A2 Step 2 has the exact text |
   | `CLAUDE.md` | P1 Task A2 Step 3 has the exact text (one-liner pointer to AGENTS.md) |

   Commit message: `feat: bootstrap shared contracts (gitignore, license, categories, AGENTS)`.

3. **Create worktrees.**
   ```bash
   git worktree add ../wisdom.p1 -b feat/p1-capture
   git worktree add ../wisdom.p2 -b feat/p2-site
   git worktree add ../wisdom.p3 -b feat/p3-imports
   ```
   All three worktrees fork from the bootstrap commit and already contain the shared files. Phase agents VERIFY these are present (P1 Tasks A1/A2, P2 Task B1, P3 Task C1) but do NOT re-create them.

4. **Dispatch three agents in parallel.** Each agent receives:
   - Working directory: its worktree path
   - Required reading: this master plan (especially §Frozen Contracts) + its phase plan
   - Instruction to use `superpowers:test-driven-development` and `superpowers:verification-before-completion`
   - Instruction to commit frequently, push branch to `origin` when done

5. **Review each branch on completion.** Diff against `main`, run that phase's tests in its worktree.

6. **Merge in order P1 → P2 → P3** to `main` via `git merge --no-ff`. Resolve any conflicts (should be near-zero per the layout above).

7. **Run verification matrix** from `main` worktree.

8. **Push `main`.** Pages deploys automatically.

9. **Cleanup worktrees:** `git worktree remove ../wisdom.p{1,2,3}`.
